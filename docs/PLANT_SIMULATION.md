# 손끝 원장 — Plant Simulation 구축 명세

> 이 문서는 **Siemens Tecnomatix Plant Simulation으로 같은 시나리오를 만들기 위한 명세**입니다.
> Unity 구현(`unity-training/`)과 웹(`agent-web/`)의 계산식을 그대로 옮겼습니다. Unity·C#·WebGL 관련 내용은 뺐습니다.
> 모든 수치는 **예시 가정값**입니다. 실제 현장 데이터로 보정해야 하며, 실제 값이라고 단정하지 않습니다.

## 1. 한 줄 요약

숙련자의 손끝 노하우(암묵지)를 "조각"으로 남겨 두고, 신입이 같은 조건에서 **작업표준서만 따를 때**와 **조각을 따를 때**의 불량률·다운타임을 비교하는 사출 라인 시뮬레이션입니다.

## 2. 시나리오: 김민준 씨의 하룻밤

- 김민준(입사 4주차 신입)이 박 조장 없이 야간 교대에서 **자동차 도어 트림 100쇼트**를 사출합니다.
- 제품에 하얀 줄(은줄)이 생기지만 인수인계에는 "특이사항 없음"만 남아 있습니다.
- 작업표준서에는 조건값만 있고, 조건은 임의로 바꿀 수 없습니다.
- 같은 밤의 조건(외기온도, 습도, 설비 연수, 근속)에서, 숙련자 조각을 따르면 불량이 줄어듭니다.

## 3. 만들 모델 (객체)

| 객체 | Plant Simulation 클래스 | 설명 |
|---|---|---|
| 원료 건조기 | `SingleProc` | 건조 시간 부족이면 은줄·기포 위험(고습 요인) |
| 사출기 (1라인, 3호기) | `SingleProc` | 1쇼트 = 1부품. 사이클 시간은 임의 값으로 둡니다 |
| 금형 | 사출기 속성 | 저온이면 덜 데워져 웰드라인·미성형 위험 |
| 트림 조립 | `ParallelProc` 또는 `SingleProc` 2대 | 작업자 2명이 트림 클립 조립 |
| 검사대 | `SingleProc` | 불량 판정 후 `Drain` 또는 불량 보관 |
| 부품 | `Entity` | 속성: `defect`(불량 여부), `defectType`(문자열) |
| 작업자 | `Worker` | 김민준(신입), 박 조장(주간·야간에는 부재), 조립 2명 |
| 상황 | `Table` 또는 변수 | 아래 4개 입력값 |
| 조각 | `TableFile` | 아래 5개 조각 |

흐름: **원료 → 건조 → 사출 → 트림 조립 → 검사 → 완제품/불량 보관**. 100쇼트가 끝나면 종료합니다.

## 4. 입력값 (상황)

| 변수 | 의미 | 기본값 | 권장 범위 |
|---|---|---|---|
| `temp` | 외기온도(℃) | 12 | -20 ~ 45 |
| `humidity` | 습도(%) | 72 | 0 ~ 100 |
| `age` | 설비 사용연수(년) | 15 | 0 ~ 50 |
| `tenure` | 작업자 근속(주) | 4 | 0 ~ 520 |

프리셋: 한겨울 새벽 (-3℃, 35%), 장마철 야간 (24℃, 90%), 열대야 (31℃, 72%), 민준 씨의 밤 (4℃, 88%).

## 5. 불량률·다운타임 계산식 (핵심)

### 5.1 상수

```
BaseDefect   = 2.5      # 기준 불량률(%)
BaseDown     = 14       # 기준 월 다운타임(h)
OnboardWeeks = 24       # 독립 작업까지 기간(주)

요인 순서   : [고습, 저온, 고온, 설비 노후, 저숙련]
DefectWeight = [0.9, 0.5, 0.4, 0.8, 1.2]
DownWeight   = [0.2, 0.3, 0.2, 1.0, 0.9]
```

### 5.2 요인 강도 f[i] (0~1로 잘라냄: clamp01)

```
f[0] 고습     = clamp01((humidity - 50) / 40)
f[1] 저온     = clamp01((15 - temp) / 20)
f[2] 고온     = clamp01((temp - 25) / 15)
f[3] 설비노후 = clamp01(age / 25)
f[4] 저숙련   = clamp01(1 - tenure / OnboardWeeks)
```

### 5.3 조각을 따랐을 때의 완화

조각 하나가 **적용(applied)** 되었고 **발동(triggered)** 조건을 만족하면, 해당 요인의 기여를 줄입니다.

```
keepDef[요인]  *= (1 - mDefect)
keepDown[요인] *= (1 - mDown)
```

표준 매뉴얼만 따르면 `keepDef = keepDown = 1` (완화 없음).

### 5.4 결과

```
contrib[i] = BaseDefect * DefectWeight[i] * f[i] * keepDef[i]
defect(%)  = min(100, BaseDefect + Σ contrib[i])
downMul    = 1 + Σ DownWeight[i] * f[i] * keepDown[i]
down(h/월) = BaseDown * downMul
```

### 5.5 쇼트별 불량 판정

같은 난수 `u`(0~1)로 두 경우를 비교해야 "조각 덕에 줄어든 불량"만 차이로 나타납니다.

```
각 쇼트마다 u = random(0,1)  (두 경우 모두 같은 u 사용)
표준    : u < defect_표준 / 100  → 표준 불량 +1
조각 적용: u < defect_조각 / 100  → 불량 +1, 유형 기록
```

불량 유형은 기여도 비율로 고릅니다(`u2` 새 난수).

```
total = BaseDefect + Σ contrib[i]
x = u2 * total
i = 0..4 순서로 x < contrib[i]이면 FactorDefect[i], 아니면 x -= contrib[i]
끝까지 못 고르면 "기타(이물·흑점)"
```

요인별 불량 유형: `FactorDefect = ["은줄·기포", "웰드라인·미성형", "휨·변형", "수축·중량 편차", "임의 조정으로 인한 불량"]`

## 7. 보상 원장 (선택 기능)

조각을 따라 생산을 마치면 발동된 조각의 `uses`가 1 올라갑니다.

```
기여 점수(작성자) = Σ [ uses * (mDefect + mDown) ]   # 해당 작성자의 모든 조각
배분액(작성자)    = 월 인센티브 재원 * (작성자 점수 / 전체 점수)
월 인센티브 재원 예시 = 1,000,000원
```

## 10. 지켜야 할 규칙

1. 조각의 조치는 **작업표준 범위 안**에서만 합니다. 조건값을 바꾸라고 하지 않습니다.
2. 모든 수치는 **예시 가정 모델**임을 화면과 보고서에 밝힙니다.
3. 숙련자는 실명 대신 **ID**로 기록합니다. 실제 인물이 아닌 가상 인물입니다.
4. 보상은 줄어든 불량 비용 안에서 지급하는 구조입니다. 실제 지급액이 아니라 배분 비율의 예시입니다.
5. 유료 서비스나 외부 API 없이 동작해야 합니다.

## 11. 구현 순서 제안

1. 입력 테이블과 상수 → 계산 메서드(5.1~5.4) 먼저 만들고, 9번 표와 맞는지 확인합니다.
2. 라인 객체(3번)와 부품 `Entity`를 만들고 100쇼트를 흘립니다.
3. 쇼트별 판정(5.5)과 불량 유형 로그를 붙입니다.
4. 조각 선택 UI(적용 on/off)와 비교 차트를 만듭니다.
5. 선택: 보상 원장(7번).
